# Ρύθμιση Stripe — τι πρέπει να κάνεις εσύ

Ο κώδικας των συνδρομών είναι έτοιμος και δοκιμασμένος. Λείπουν μόνο δύο τιμές που
πρέπει να πάρεις από το Stripe Dashboard.

---

## 0. ΕΠΕΙΓΟΝ πρώτα: κάνε roll το εκτεθειμένο κλειδί

Το **live** secret key (`sk_live_51U0rhS…`) στάλθηκε σε συνομιλία, άρα θεωρείται
εκτεθειμένο. Ένα live secret key μπορεί να κινήσει πραγματικά χρήματα και να διαβάσει
δεδομένα πελατών.

1. <https://dashboard.stripe.com> → **Developers** → **API keys**
2. Στο **Secret key** → μενού `⋯` → **Roll key**
3. Επίλεξε άμεση λήξη του παλιού

Δεν χρησιμοποιήθηκε πουθενά στον κώδικα — δεν μπήκε ποτέ σε αρχείο.

---

## 1. Πάρε το κλειδί δοκιμών

**Πάνω δεξιά στο Dashboard, ενεργοποίησε τον διακόπτη «Test mode».**

Developers → API keys → αντίγραψε το **Secret key** που αρχίζει με `sk_test_…`.

Το *publishable key* (`pk_…`) **δεν χρειάζεται** — η ροή πληρωμής γίνεται εξ ολοκλήρου
από τον server, ώστε τίποτα ευαίσθητο να μη φτάνει στον browser.

> Το πρόθεμα του κλειδιού είναι ο διακόπτης περιβάλλοντος. `sk_test_` σημαίνει καμία
> πραγματική χρέωση· `sk_live_` σημαίνει αληθινά χρήματα. Δεν υπάρχει άλλη ρύθμιση να
> ξεχάσεις να αλλάξεις.

---

## 2. Δημιούργησε προϊόν και τιμή 3€/μήνα

Πιο εύκολα από το Dashboard: **Product catalog** → **Add product**

- Name: `NutreLuma`
- Pricing model: **Recurring**
- Amount: `3.00` — Currency: **EUR** — Billing period: **Monthly**

Πάτα **Save** και αντίγραψε το **Price ID** (αρχίζει με `price_…`).

> ⚠️ **`price_…`, όχι `prod_…`.** Το Dashboard δείχνει και τα δύο δίπλα-δίπλα και
> μπερδεύονται εύκολα. Με `prod_…` όλα φαίνονται σωστά μέχρι να πατήσει ο χρήστης
> «Πληρωμή». Αν έχεις μόνο το `prod_…`, βρες το price:
>
> ```sh
> curl -sS -u "$STRIPE_KEY:" "https://api.stripe.com/v1/prices?product=prod_XXX&active=true"
> ```

<details>
<summary>Ή με curl, αν προτιμάς</summary>

```bash
STRIPE_KEY=sk_test_XXX

curl -sS https://api.stripe.com/v1/products \
  -u "$STRIPE_KEY:" -d name="NutreLuma"

curl -sS https://api.stripe.com/v1/prices \
  -u "$STRIPE_KEY:" \
  -d product=prod_XXX \
  -d unit_amount=300 \
  -d currency=eur \
  -d "recurring[interval]=month"
```

</details>

## 3. Βάλε τις δύο τιμές στο NAS

```sh
export PATH=/share/CACHEDEV1_DATA/.qpkg/container-station/bin:$PATH
export HOME=/tmp/nutreluma-deploy; export DOCKER_CONFIG=$HOME/.docker
cd /share/CACHEDEV1_DATA/Container/nutreluma

sed -i 's|^STRIPE_SECRET_KEY=.*|STRIPE_SECRET_KEY=sk_test_ΤΟ_ΔΙΚΟ_ΣΟΥ|' .env
sed -i 's|^STRIPE_PRICE_ID=.*|STRIPE_PRICE_ID=price_ΤΟ_ΔΙΚΟ_ΣΟΥ|' .env

docker compose --env-file .env up -d --force-recreate --no-build web
```

Δεν χρειάζεται rebuild — μόνο ρυθμίσεις αλλάζουν.

Επιβεβαίωσε ότι έφτασαν όντως στο container (το `.env` στον δίσκο μπορεί να διαφέρει
από αυτό που τρέχει):

```sh
docker inspect nutreluma-web --format '{{range .Config.Env}}{{println .}}{{end}}' \
  | grep -E "^(BILLING_ENABLED|STRIPE_)"
```

Αν δεν εμφανίζονται καθόλου, λείπουν από το `environment:` του `docker-compose.yml`.

### Ο λογαριασμός πρέπει να μπορεί να χρεώνει

```sh
curl -sS -u "$STRIPE_KEY:" https://api.stripe.com/v1/accounts/ΤΟ_ACCT_ID | grep charges_enabled
```

Με `charges_enabled: false` οι πληρωμές δεν ολοκληρώνονται, ακόμη κι αν όλα τα άλλα
είναι σωστά. Δες το **Dashboard → Settings → Payment methods** για τυχόν εκκρεμότητες·
αν τα requirements είναι κενά, ο λογαριασμός είναι απλώς υπό έλεγχο από τη Stripe.

---

## 4. Δοκίμασε τη ροή

1. Μπες με λογαριασμό **που δεν είναι ADMIN** (π.χ. `demo@nutreluma.local`)
2. Πήγαινε στη **Συνδρομή** από το μενού
3. Πάτα «Συνδρομή 3,00€/μήνα»
4. Στη σελίδα Stripe βάλε **δοκιμαστική κάρτα**:

| Πεδίο | Τιμή |
|---|---|
| Αριθμός | `4242 4242 4242 4242` |
| Ημερομηνία | οποιαδήποτε μελλοντική (π.χ. `12/30`) |
| CVC | οποιοδήποτε τριψήφιο |
| Όνομα / διεύθυνση | οτιδήποτε |

Αναμενόμενο: επιστροφή στο `/billing` με μήνυμα «Η συνδρομή ενεργοποιήθηκε», κατάσταση
**Ενεργή**, και μία πληρωμή 3,00€ στο ιστορικό.

**Κάρτα που απορρίπτεται** για δοκιμή αποτυχίας: `4000 0000 0000 0002`

---

## 5. Μετάβαση σε πραγματικές πληρωμές

Όταν είσαι έτοιμος:

1. Απενεργοποίησε το «Test mode» στο Dashboard
2. Ξαναδημιούργησε το προϊόν/τιμή **σε live mode** (τα test δεν μεταφέρονται)
3. Βάλε το **νέο** `sk_live_…` και το live `price_…` στο `.env`
4. `docker compose up -d --force-recreate --no-build web`

> ⚠️ Από εκείνη τη στιγμή κάθε πληρωμή είναι αληθινή. Θυμήσου και τις φορολογικές
> υποχρεώσεις που συζητήσαμε — η είσπραξη από τρίτους δημιουργεί υποχρέωση
> τιμολόγησης ανεξάρτητα από πάροχο.

## Χωρίς Stripe — πληρωμές IRIS, IBAN ή Buy Me a Coffee

Δεν χρειάζεσαι καθόλου Stripe για να δέχεσαι χρήματα. Η εφαρμογή έχει **χειροκίνητη
ενεργοποίηση**:

1. Ο χρήστης σου στέλνει τα χρήματα με όποιον τρόπο θέλεις
2. Πηγαίνεις στο **`/admin/users`** (φαίνεται μόνο σε ADMIN)
3. Βρίσκεις τον χρήστη, βάζεις μήνες και σημείωση («IRIS 05/08, ref ABC123»)
4. Πατάς **Παράταση**

Η πρόσβαση παρατείνεται αμέσως και καταγράφεται πληρωμή στο ιστορικό του. Αν πληρώσει
πριν λήξει η τρέχουσα περίοδος, ο χρόνος **προστίθεται** αντί να χάνεται.

---

## Πώς λειτουργεί η πρόσβαση

| Κατάσταση | Τι μπορεί να κάνει |
|---|---|
| **Δοκιμή** (3 ημέρες από την εγγραφή) | Τα πάντα |
| **Ενεργή συνδρομή** | Τα πάντα |
| **Σε επιβεβαίωση** (χάρη 3 ημερών) | Τα πάντα — καλύπτει καθυστέρηση χρέωσης |
| **Έληξε** | Βλέπει, διορθώνει, εξάγει και διαγράφει· **δεν** προσθέτει νέα |
| **ADMIN** | Τα πάντα, πάντα |

Κλειδώνουν ακριβώς τρεις ενέργειες: νέο γεύμα, επανάληψη ανάλυσης AI, νέα καταχώριση
βάρους. Όλα τα υπόλοιπα — προβολή, διόρθωση παλιών γευμάτων, προφίλ, εξαγωγή δεδομένων,
διαγραφή λογαριασμού — παραμένουν ανοιχτά.

Για να απενεργοποιήσεις τελείως τη χρέωση: `BILLING_ENABLED=false` στο `.env`.
