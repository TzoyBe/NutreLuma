# Email — οδηγίες ρύθμισης

Το email χρειάζεται **μόνο** για την επαναφορά κωδικού. Χωρίς αυτό η εφαρμογή
λειτουργεί κανονικά, αλλά όποιος ξεχάσει τον κωδικό του κλειδώνεται μόνιμα έξω.

---

## 1. Μην στήσεις δικό σου mail server

Είναι ο κλασικός τρόπος να χαθεί ένα σαββατοκύριακο και τα emails να καταλήγουν
στα ανεπιθύμητα:

- Οι IP των VPS και των οικιακών συνδέσεων είναι **προεπιλεγμένα σε
  blocklists**. Gmail και Outlook θα τα πετάνε στα spam ή θα τα απορρίπτουν.
- Θέλει σωστό SPF, DKIM, DMARC **και reverse DNS (PTR)** — και συνεχή
  παρακολούθηση της φήμης της IP, όχι μία φορά.
- Η Hetzner και οι περισσότεροι πάροχοι **κλείνουν τη θύρα 25** εξ ορισμού.
- Από το 2024 Google και Yahoo επιβάλλουν αυστηρότερους κανόνες σε αποστολείς.

Το χειρότερο σενάριο δεν είναι «δεν φεύγει το email» — είναι ότι **φεύγει και
δεν φτάνει**, χωρίς να το μάθεις.

---

## 2. Επιλογή παρόχου

| Πάροχος | Δωρεάν | Σημείωση |
|---|---|---|
| **Brevo** | 300 email/ημέρα | Γαλλική, δεδομένα σε ΕΕ — καλή επιλογή για GDPR |
| **Resend** | 3.000/μήνα | Πολύ απλό, επιλογή περιοχής ΕΕ |

Και οι δύο υλοποιούνται μέσω **HTTP API**, όχι SMTP: καμία επιπλέον εξάρτηση
στο project, και δεν μπλοκάρονται από firewalls που κλείνουν τη θύρα 587.

---

## 3. Brevo

1. Λογαριασμός στο [app.brevo.com](https://app.brevo.com).
2. **Senders, Domains & Dedicated IPs → Domains → Add a domain**:
   `nutreluma.com`.
3. Η Brevo δίνει εγγραφές **DKIM** και **DMARC** (TXT). Πρόσθεσέ τες στο
   Cloudflare DNS του domain και πάτα **Authenticate**.
4. **SMTP & API → API Keys → Generate a new API key**. Αντίγραψέ το.

```env
EMAIL_PROVIDER=brevo
EMAIL_API_KEY=xkeysib-…
EMAIL_FROM=noreply@nutreluma.com
EMAIL_FROM_NAME=NutreLuma
```

---

## 4. Resend

1. Λογαριασμός στο [resend.com](https://resend.com).
2. **Domains → Add Domain** → `nutreluma.com` → **Region: EU (Ireland)**.
3. Πρόσθεσε τις εγγραφές DNS που δίνει (MX + TXT για DKIM/SPF) στο Cloudflare.
4. **API Keys → Create API Key** με δικαίωμα *Sending access*.

```env
EMAIL_PROVIDER=resend
EMAIL_API_KEY=re_…
EMAIL_FROM=noreply@nutreluma.com
EMAIL_FROM_NAME=NutreLuma
```

> Το `EMAIL_FROM` **πρέπει** να ανήκει σε domain που επαλήθευσες. Αποστολή από
> `@gmail.com` απορρίπτεται από τους παρόχους.

## 5. Εφαρμογή στο NAS

```sh
export PATH=/share/CACHEDEV1_DATA/.qpkg/container-station/bin:$PATH
export HOME=/tmp/nutreluma-deploy; export DOCKER_CONFIG=$HOME/.docker
cd /share/Container/nutreluma

nano .env   # συμπλήρωσε τις τέσσερις μεταβλητές

docker compose -f docker-compose.yml -f docker-compose.tunnel.yml \
  --env-file .env up -d --force-recreate --no-build web
```

Επιβεβαίωση ότι φορτώθηκαν:

```sh
docker inspect nutreluma-web --format '{{range .Config.Env}}{{println .}}{{end}}' \
  | grep -E "^EMAIL_" | sed -E 's/(API_KEY=).+/\1<κρυμμένο>/'
```

## 6. Δοκιμή χωρίς πάροχο

Με `EMAIL_PROVIDER=log` (η προεπιλογή) η ροή δουλεύει πλήρως — απλώς το μήνυμα
γράφεται στα logs αντί να σταλεί. Χρήσιμο για να δοκιμάσεις την επαναφορά πριν
φτιάξεις λογαριασμό:

```sh
# Ζήτα επαναφορά από το UI, μετά:
docker compose logs --tail 50 web | grep email_not_sent_logged_only
```

Στο σώμα του μηνύματος υπάρχει ο πλήρης σύνδεσμος `/reset-password?token=…`.

---

## 7. Δοκιμή με πραγματικό πάροχο

1. `https://www.nutreluma.com/forgot-password`
2. Δώσε το email ενός υπαρκτού λογαριασμού.
3. Έλεγχος στα logs:

```sh
docker compose logs --tail 50 web | grep -E "email_sent|email_failed|password_reset"
```

- `email_sent` → στάλθηκε.
- `email_failed` → δες το `detail`: περιέχει την ακριβή απάντηση του παρόχου
  (κακό κλειδί, μη επαληθευμένο domain κ.λπ.). Ο χρήστης **δεν** βλέπει σφάλμα
  — σκόπιμα, για να μην αποκαλύπτεται αν το email υπάρχει.

## 8. Πώς προστατεύεται η ροή

| Μέτρο | Γιατί |
|---|---|
| Ίδια απάντηση για υπαρκτό και ανύπαρκτο email | Αλλιώς η φόρμα γίνεται εργαλείο απαρίθμησης πελατών |
| Στη βάση αποθηκεύεται **SHA-256** του token | Διαρροή βάσης δεν επιτρέπει κατασκευή έγκυρου συνδέσμου |
| Token μιας χρήσης, λήξη 60 λεπτά | Περιορίζει το παράθυρο εκμετάλλευσης |
| Νέα αίτηση ακυρώνει τις προηγούμενες | Δεν μένουν πολλοί ενεργοί σύνδεσμοι ταυτόχρονα |
| Όριο 5 αιτήσεων/ώρα ανά email, 15 ανά IP | Αποτρέπει «βομβαρδισμό» γραμματοκιβωτίου και σάρωση |
| Όριο 20 προσπαθειών εξαργύρωσης/ώρα ανά IP | Αποτρέπει μαντεψιά token |
| Ίδιο μήνυμα για άγνωστο / ληγμένο / χρησιμοποιημένο | Δεν διαρρέει πληροφορία για την κατάσταση του token |
| `passwordChangedAt` ακυρώνει **όλες** τις συνεδρίες | Κλεμμένο session cookie παύει να ισχύει μετά την επαναφορά |
| Καμία αυτόματη σύνδεση μετά την επαναφορά | Αν ο σύνδεσμος έπεσε σε λάθος χέρια, δεν δίνει άμεση πρόσβαση |

Η ίδια ακύρωση συνεδριών ισχύει και για τη **χειροκίνητη αλλαγή κωδικού** από
τις Ρυθμίσεις: αν ο χρήστης την κάνει επειδή υποπτεύεται παραβίαση, όλες οι
άλλες συσκευές αποσυνδέονται.

## 9. Επόμενα βήματα (δεν έχουν υλοποιηθεί)

Η υποδομή email είναι γενική (`EmailProvider` interface + πρότυπα ανά γλώσσα),
οπότε τα παρακάτω χρειάζονται μόνο νέο πρότυπο και σημείο κλήσης:

- Επιβεβαίωση email κατά την εγγραφή
- Ειδοποίηση λήξης δοκιμαστικής περιόδου
- Απόδειξη πληρωμής
- Εβδομαδιαία αναφορά
